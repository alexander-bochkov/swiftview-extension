Image embedding test page

Each card places an image in a different way. Press and hold the left mouse button on it and check what your extension finds. Every image is generated inside this file, so no network is needed. Images carry a label and size, and a white corner triangle so flips and rotations are visible.

The line under each title says what to expect. Cards tagged T are traps that hide the image from event.target. The bar at the bottom shows what the page itself sees on mousedown. Chrome needs "Allow access to file URLs" on for content scripts on file:// pages, or serve this folder with python3 -m http.server.

Image elements

Tags whose job is to show an image.

#1<img src>

Target is the <img>. Read currentSrc. The second image adds loading=lazy and fetchpriority, which change nothing about the source. 

<img src="photo.jpg" alt="..." width="240">
<img src="photo.jpg" loading="lazy" decoding="async" fetchpriority="low">

#2<img srcset> (w and x descriptors)

A normal screen loads the 400w and 1x candidates. The best candidates are 1600w and 3x, and currentSrc alone will not find them. 

<img src="a-400.jpg"
     srcset="a-400.jpg 400w, a-800.jpg 800w, a-1600.jpg 1600w"
     sizes="240px" width="240">
<img src="b-1x.jpg" srcset="b-1x.jpg 1x, b-2x.jpg 2x, b-3x.jpg 3x" width="240">

#3<picture> with <source>

Target is the <img>, never a <source>. The red unsupported-type source must be skipped. Which candidate wins depends on window width (900px breakpoint); the largest usable one is the wide source. 

<picture>
  <source type="image/x-unsupported" srcset="bad.xyz">
  <source media="(min-width: 900px)" srcset="wide.jpg">
  <source media="(max-width: 899px)" srcset="narrow.jpg">
  <img src="fallback.jpg" width="240">
</picture>

#4Lazy-loaded image (data-* attributes)

src is a 1x1 placeholder or missing. The real URL is in data-src, data-srcset or data-original. The viewer should show the 1200x800 original, not the placeholder. Nothing on this page swaps them in. 

<img src="placeholder.gif" data-src="full.jpg">
<img src="placeholder.gif" data-srcset="s.jpg 600w, l.jpg 1200w">
<img data-original="full.jpg">

#12SVG file in <img>

Two SVG data URIs, base64 and percent-encoded. The viewer must render vector images, and naturalWidth comes from the SVG width attribute. 

<img src="logo.svg">
<img src="data:image/svg+xml;base64,...">
<img src="data:image/svg+xml;utf8,%3Csvg ...">

#15<input type="image">

Target is the input. The source is input.src. The form does not submit. 

<input type="image" src="button.png" alt="Send">

CSS images

Images that come from stylesheets, not from markup.

#5CSS background-image

Read getComputedStyle(el).backgroundImage. Cases: plain, a url() under a gradient overlay, a gradient only (no image, must be ignored), and a sprite (a tile of a wider sheet). 

.hero { background: url(hero.jpg) center/cover no-repeat }
.dark { background: linear-gradient(#0006,#0006), url(hero.jpg) }
.icon { background: url(sprite.png) -120px 0 no-repeat }

#6Pseudo-element background (::before)

Pseudo-elements never receive events, so the target is the host div. Read getComputedStyle(host, '::before'). 

.card::before { content: ""; position: absolute; inset: 0;
                background: url(bg.jpg) center/cover }

#7CSS content: url()

The first is an ::after image. The second is an <img> whose src (red, hidden) differs from what is rendered (green) because of a CSS content rule. Decide which one the viewer shows. 

.badge::after { content: url(badge.png) }
img.swapped { content: url(other.png) }

#8list-style-image, border-image, mask-image

Rare in practice. A mask is an alpha shape rather than a picture, so most extensions should skip it. 

ul { list-style-image: url(bullet.png) }
.frame { border-image: url(frame.png) 30 round }
.icon { mask-image: url(icon.svg) }

#9CSS image-set()

The computed value contains three candidates. The best is 3x. Chrome may report it as -webkit-image-set(...). 

.el { background-image: image-set(url(1x.jpg) 1x, url(2x.jpg) 2x, url(3x.jpg) 3x) }

SVG

Vector graphics and images placed inside SVG.

#10Inline <svg>

The target is a child such as <circle> or <path>. Use closest('svg') and serialize it. The star is a <use> that points at a <symbol> defined elsewhere, so the serialized copy must include the symbol. 

<svg viewBox="0 0 240 160"><circle cx="80" cy="76" r="38"/>...</svg>
<svg><use href="#icon-star"/></svg>

#11<image> inside <svg>

Two <image> elements. One uses href, the other legacy xlink:href. 

<svg>
  <image href="a.png" width="200" height="140"/>
  <image xlink:href="b.png" x="220" width="200" height="140"/>
</svg>

Canvas and video

Images that are drawn or attached to media elements.

#13<canvas> (2D and WebGL)

The 2D canvas is 480x300 drawn at 240x150 CSS px, and toBlob() works because the drawn image is a data URI. The WebGL canvas has no preserveDrawingBuffer, so toDataURL() usually returns a blank image. 

<canvas width="480" height="300"></canvas>
ctx.drawImage(img, 0, 0);  canvas.toBlob(cb)

#14<video poster>

Target is the <video>. The image is video.poster. The element has no video source on purpose. 

<video controls poster="preview.jpg" src="movie.mp4">

Embedded documents

Images inside other documents or other elements.

#16<object> and <embed>

Image documents embedded through plugin-style elements. Read the data or src attribute. 

<object data="pic.png" type="image/png"></object>
<embed src="pic.png" type="image/png">

#17<iframe> containing an image

The image lives in another document. The content script must run in this frame (all_frames and match_about_blank in the manifest), because events do not cross frame borders. 

<iframe srcdoc="<img src=pic.png>"></iframe>

#18Image map (<map> and <area>)

In Chrome the mousedown target is the <area>, while elementsFromPoint() returns the <img>. Resolve the image through img[usemap="#name"] or use the point lookup. 

<img src="pic.jpg" usemap="#m1">
<map name="m1"><area shape="rect" coords="0,0,160,200" href="#left"></map>

Legacy

Old attributes that browsers still honor.

#19Legacy background attribute

Old HTML attribute on <table> and <td>. It also appears in the computed backgroundImage.

table background
td background 
<table background="tile.png">...</table>
<td background="tile.png">

Traps

Cases where the mousedown target is not the image.

T1Transparent overlay above the image

event.target is the empty link, not the image. Find the <img> in document.elementsFromPoint(). 

<div style="position:relative"><img src="a.jpg"><a href="#" style="position:absolute;inset:0"></a></div>

T2Image with pointer-events: none

The target is the parent div, and elementsFromPoint() skips the image too, because hit-testing ignores elements with pointer-events: none. Fall back to scanning images whose bounding rect contains the pointer. 

.pe img { pointer-events: none }

T3Open shadow root

Document listeners see the host as event.target. composedPath()[0] is the inner <img>. 

host.attachShadow({ mode: 'open' })

T4Closed shadow root

Both composedPath() and elementsFromPoint() stop at the host. An extension can reach the inside with chrome.dom.openOrClosedShadowRoot(host). 

host.attachShadow({ mode: 'closed' })

T5Thumbnail inside a link to the full image

The link's href (a blob URL, set by script) points to a 1600x1067 version. Decide whether the viewer prefers the link target. A held mouse button on a link also starts a native link drag. 

<a href="full.jpg"><img src="thumb.jpg"></a>

T6Images created by JavaScript

Three images built at runtime: createElement, new Image() with srcset, and a blob: URL from canvas.toBlob(). Blob URLs only work in the page that made them. 

const im = new Image();
im.srcset = 'a.jpg 400w, b.jpg 1200w';
im.src = URL.createObjectURL(blob);

T7Rotated image, object-fit, circular clip

The image is transformed, cropped by object-fit: cover and clipped by a rounded container. Hit-testing should still find it, and the displayed size differs from naturalWidth. 

.clip { overflow: hidden; border-radius: 50% }
.clip img { object-fit: cover; transform: rotate(6deg) scale(1.25) }

T8Text on top of a background image

The target is the heading. The image is a background on its ancestor, which does appear in elementsFromPoint().

Headline over a background image

<div class="hero"><h4>Headline</h4></div>
.hero { background: url(hero.jpg) center/cover }
