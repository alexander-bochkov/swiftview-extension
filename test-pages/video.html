Video test page

Each card places a video in a different way. Open the context menu on it, with a right click or a long press, and choose "Open with SwiftView". The line under each title says what should happen. The clip is recorded from a canvas when the page loads, two seconds of a moving square with a frame counter, so no network is needed. The links to a video file use a data: url of the same clip.

Cards with a red tag are traps where the element under the pointer is not the video. Chrome needs "Allow access to file URLs" on for content scripts on file:// pages, or serve this folder with python3 -m http.server.

Keyboard

With a video open, the focus is on it and the keys of the browser's controls work. Check them on the first card.

  • Space and Enter play and pause.
  • Left and Right seek. Up and Down change the volume.
  • Home and End jump to the start and to the end.
  • Page Up and Page Down do nothing, and the page behind doesn't scroll.
  • Escape closes the viewer. A click on the dark area around the video closes it too, and moves the focus away from the video until it's clicked again.

Video elements

Ways a page can put a video on screen.

#1<video src>

Opens the video with the controls, paused at the start. 

<video src="clip.webm" controls></video>

#2<video> with <source>

Opens the source the browser picked, the WebM one. The unsupported one is never picked, so it's never opened. 

<video controls>
  <source src="clip.xyz" type="video/x-unsupported">
  <source src="clip.webm" type="video/webm">
</video>

#3<video poster> with a source

Opens the video, not the poster. The menu is on a video, so the poster is never a candidate. 

<video controls poster="preview.jpg" src="clip.webm"></video>

#4<video poster> without a source

The menu item appears but nothing opens: Chrome reports no url for a video without a source, and the poster isn't one. 

<video controls poster="preview.jpg"></video>

#5Autoplaying loop without controls

Opens the clip with the controls, from the start and paused: the viewer loads its own copy of it. 

<video src="clip.webm" autoplay loop muted playsinline></video>

#6<iframe> containing a video

Opens the video. The content script runs in the frame too, so the frame answers with the candidates. 

<iframe srcdoc="<video src=clip.webm controls>"></iframe>

#7Video inside a link

Opens the video behind the link first. The file behind this one is missing, so the viewer falls back to the video itself. 

<a href="full.mp4"><video src="clip.webm" controls></video></a>

#8Thumbnail inside a link to a video

Opens the video behind the link, a data: url set by the script and typed by its MIME type, not the thumbnail. 

<a href="clip.webm"><img src="thumb.jpg"></a>

Load errors

What the viewer does when a candidate doesn't load.

#9Missing file

Nothing loads: the error, with only the close button. The poster is only there to give the video a size on the page. 

<video src="missing.webm" controls poster="preview.jpg"></video>

#10Unsupported format

Nothing loads: the browser can't play the type. 

<video src="data:video/x-unsupported;base64,AAAA" controls></video>

#11Corrupt file

Nothing loads: the file is only the start of a WebM header. 

<video src="data:video/webm;base64,GkXfo0Ag..." controls></video>

#12Thumbnail inside a link to a missing video

The link fails, so the viewer falls back to the thumbnail and opens it as an image. 

<a href="missing.mp4"><img src="thumb.jpg"></a>

Traps

Cases where the element under the pointer is not the video.

#13Transparent overlay above the video

No menu item: the menu sees the empty link, not the video under it. 

<div style="position:relative"><video src="clip.webm"></video><a href="#" style="position:absolute;inset:0"></a></div>

#14Video with pointer-events: none

No menu item: hit-testing skips the video, for the menu too. 

.pe video { pointer-events: none }
